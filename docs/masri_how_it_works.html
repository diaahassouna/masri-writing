How Masri Works

What Masri is

Masri is a proposed canonical orthography for Egyptian Arabic — not merely a transliteration scheme. It is designed to take the many ways people already write Egyptian Arabic (in Arabic script, in Franco/Arabizi, or in a mix of both) and normalize them into one consistent written form, which can then be represented in three different ways depending on the environment.

The problem it addresses: Egyptian Arabic is spoken by tens of millions of people every day, but has no single standard way to write it. Arabic script is used for it informally, but the language's own grammars and dictionaries are almost all written for Modern Standard Arabic, not the spoken dialect. Franco/Arabizi fills the gap online, but every writer spells the same word differently, and it isn't a designed system so much as an improvised workaround built around number-substitutes like 3, 7, and 2. Masri is a proposal to give the spoken language an orthography of its own.

Arabic-script → canonical Masri normalization is part of Masri's conceptual architecture and design goal, but isn't implemented in the interactive converter yet — typing Arabic script into it currently passes the text through unchanged rather than normalizing it.

Normalization vs. representation

Not every conversion on this site is the same kind of operation, and the site tries to name them accurately rather than calling everything "transliteration":

Normalization / canonicalization

Converting Arabic script, Franco, or mixed input into one preferred canonical form. Example: 3ashan and ashan both normalize to the same canonical word. This is what the converter's dictionary and rule set do.

Romanization / representation

Re-expressing the canonical Masri orthography in a different character set for a different environment. Converting Tier 2 to DRS is representation, not normalization — the underlying word and its rules don't change, only the glyphs used to write it.

Transliteration

Mapping from one writing system to another while preserving the source's own spelling/structure as closely as possible — the approach used by scholarly transcription systems for Arabic (see the prior-attempts history). Masri's Arabic-to-canonical step is closer to normalization, because it deliberately standardizes rather than mirrors the source spelling.

Tier 1 · Tier 2 · DRS

These are three representations of one underlying orthography, not three competing systems.

Tier 2 — the full canonical orthography

The reference form of Masri. Uses the full 37-letter inventory, including the Coptic, Greek, and Latin-extended letters that give the system precise, mostly one-to-one grapheme coverage. This is what the Alphabet page documents in full.

Tier 1 — the ASCII-compatible form

The same words, spelled with plain Latin letters and digraphs (sh, kh, gh) in place of the Coptic/Greek/Latin-extended letters, for ordinary keyboards, casual typing, and environments with limited Unicode support. Tier 1 letters are representations of specific Tier 2 graphemes, not a separate alphabet — see the digraph and numeral mapping tables on the converter page.

DRS — the Latin-extended romanization

Diaa Romanization System: Tier 2's own alphabet, with a keyboard-safe Latin substitute swapped in only for the handful of Coptic/Greek glyphs that aren't on a standard keyboard (e.g. Θ→Ŧ, Ϩ→Ħ). Every other letter is identical to Tier 2. Full table on the DRS page.

Because DRS substitutes a small, fixed set of characters, converting Tier 2 → DRS is mechanical and reversible by table lookup. The harder direction is Franco/Arabic-script → canonical Masri: that step depends on the rule types described below, and some cases (gemination, vowel length, formal/merger consonant choices) aren't fully recoverable from casual input alone — the site does not claim that conversion is lossless in that direction.

Phonology vs. orthography

Masri is sometimes summarized as "one sound, one letter." That is a useful slogan and a real design goal, but it isn't literally true of the finished system, and the site is explicit about the two kinds of exception:

Documented sound mergers

In the Cairene reference dialect, θ (ث) is pronounced /s/ and ð (ذ) is pronounced /z/ in ordinary speech; ظ commonly merges toward ض in many contexts; and the Cairene realization of ق merges with the glottal stop ء. Masri keeps the historical letters distinct in Tier 2 (so θ/ð/ẓ exist as their own graphemes) while Tier 1's everyday mode and the "casual" toggle can spell some of these phonetically (s/z) instead. Both choices are documented, not silently applied.

Orthography that preserves identity over pronunciation

Some Masri spellings deliberately don't track surface pronunciation. The clearest example: the definite article is always spelled el, even where Cairene speech assimilates it to the following consonant (sun letters). Masri prioritizes one consistent spelling over transcribing that assimilation, the same way English "the" is spelled one way regardless of how it's actually pronounced before a vowel or consonant.

How Egyptians pronounce something is not automatically identical to how Masri chooses to spell it. That's a strength of treating Masri as an orthography rather than a phonetic transcript — see Terminology for the vocabulary this page uses to keep those two things separate.

Terminology

Phoneme
An underlying sound category a language treats as distinct — e.g. Egyptian Arabic /ʕ/ (ع).
Phonetic realization
How a sound is actually pronounced in a specific context, which can vary even when the underlying phoneme doesn't.
Grapheme
A written unit or symbol — a Masri letter, in this context.
Orthography
The set of rules that determine the canonical spelling of a language — what Masri itself is.
Transliteration
Mapping between writing systems while preserving the source's own spelling as closely as possible.
Romanization
Representing a language or script using Latin characters — what DRS does to Tier 2.
Normalization / canonicalization
Converting multiple possible inputs (Arabic script, Franco, mixed) into one preferred canonical representation.

Rule types

Framing every conversion decision by type makes the system easier to audit today and easier to implement in software later:

DeterministicAlways applies the same way, regardless of context — e.g. the numeral→letter substitutions (3→Ⲵ, 7→ϩ).
ContextualDepends on neighboring characters — e.g. word-initial glottal stop being silent, but written mid-word or finally.
LexicalDepends on a known word being present in the standardized word list — e.g. 3ashan → Ⲵaϣān with a long vowel the input didn't spell out.
HeuristicA best-effort interpretation of ambiguous input where no rule or dictionary entry resolves it outright.
Human reviewCannot be reliably resolved from the input alone (e.g. some gemination and vowel-length cases) — flagged rather than guessed.

Edge cases

Rather than claim the system has no ambiguity, here are the cases that genuinely require a rule — and where that rule still leaves room for judgment:

CaseMasri's ruleAmbiguity
ع (ʿayn)Always written as its own letter, Ⲵ in Tier 2 / backtick in Tier 1 — see the ع rule above.None once recognized as ع rather than glottal stop or hamza; the ambiguity is purely on the input side (Franco writers often use 3 for it and 2 for hamza/ق, so the converter has to tell them apart from context).
ق / ء (Cairene)Treated as one glottal-stop phoneme, written Ɐ in Tier 2 (Rule 5); formal q is reserved for MSA/formal registers.Deciding when a given word should use the formal q instead of the Cairene glottal merger is a lexical/register choice, not something the spelling of the input alone determines.
Word-initial glottal stopAlways silent in spelling, whatever its etymology (Rule 3).None — this is a deterministic rule.
GeminationDoubled consonants are written doubled; long vowels are written doubled or with a macron (Rule 1).Casual Franco input rarely marks gemination explicitly, so recovering it from unmarked input is a lexical/heuristic judgment, not a deterministic conversion.
Vowel lengthShort vowels are optional in fluent writing; long vowels use doubling/macrons.Same as gemination — length isn't always recoverable from Franco input without a dictionary hit.
θ/ð mergers (ث/ذ)Tier 2 keeps θ/ð as distinct historical letters; Tier 1 everyday mode and the casual toggle can spell them phonetically as s/z.Which spelling is "correct" for a given register is a project decision the site states explicitly rather than picking silently.
Loanwords / formal vocabularyP and V are treated as independent letters (Rule 6), used mainly for loanwords and words with those original phonemes.None once a word is recognized as a loanword; recognizing it as one in the first place is a lexical lookup, not a general rule.

How this compares to other approaches

Egyptian Arabic already has several ways of being written down. They solve different problems, and Masri doesn't claim to make the others obsolete — its distinct claim is narrower: canonical orthography, input method, and romanization are three different things, and most existing approaches only address one of them.

SystemPrimary purposeWhat it optimizes for
Arabic scriptMainstream everyday Egyptian Arabic writingFamiliarity — everyone already reads it; no standard dialectal spelling convention, though.
Franco / ArabiziInformal digital writingZero setup on any keyboard; optimizes for speed of adoption, not consistency between writers.
Scholarly transcription (e.g. the Orientalist grammars)Linguistic analysis for specialistsPhonetic precision for trained readers — see Prior Attempts for the history.
EG-LangLatin-based Egyptian Arabic orthographyKeyboard-typable Latin letters with a phonological system worked out in detail; doesn't distinguish canonical spelling from romanization as separate layers.
Masri Tier 1ASCII-compatible representation of MasriTypability on any keyboard, no Unicode input needed.
Masri Tier 2Full canonical Masri orthographyPrecise, mostly one-to-one grapheme coverage using Egypt's own historical scripts.
DRSLatin-extended romanization of Masri Tier 2A Latin-only stand-in for Tier 2 in environments that can't render Coptic/Greek glyphs.

None of these is objectively better in every respect — a librarian cataloguing books needs scholarly transcription, not Masri; someone texting a friend already has Franco. Masri's proposal is specifically for readers who want one consistent canonical spelling that Franco doesn't provide, with the choice of three representations (Tier 1, Tier 2, DRS) depending on where they're writing.
